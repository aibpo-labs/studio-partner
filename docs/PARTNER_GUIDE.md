# 合作伙伴适配与使用指南

Studio Partner 是可二次开发的文本、语音客服工作台。机器人配置和对话通过 LatenTX Voice PaaS 提供；Design Agent 负责交互生成配置文件。合作伙伴可以替换品牌、修改业务表单或单独复用 H5。

## 1. 准备接入信息

| 服务 | 需要准备 | 用途 |
| --- | --- | --- |
| Voice PaaS | 服务地址、API Key、可用模型 | 机器人草稿、发布、IM、网页语音和通话记录 |
| Design Agent | 服务基址、访问凭证、已发布的 Agent ID，可选 Release ID | 多轮 Design、文件输入和配置文件输出 |

Voice PaaS 默认地址为 `https://api.latenth.com`，具体模型和权限由服务提供方开通。Design Agent 的地址及凭证由服务提供方单独提供；两套凭证不能互换。基址应包含服务方要求的路径前缀，但不要拼上会话或运行接口路径。

只试用 IM 和语音时，可先通过环境变量配置 Voice PaaS；当前连接表单会要求同时填写 Design 信息。连接检查只确认访问与资源可用，不等于一次真实对话已经验收。

## 2. 安装与启动

需要 Node.js **22.9 或更高版本**、npm，以及访问服务和 npm 依赖源的网络。获取本仓库源码后，在项目根目录执行：

```bash
npm ci
cp .env.example .env
# 编辑 .env，填写自己的连接信息
npm run sync-sdk
npm run build
npm test
npm start
```

`sync-sdk` 下载公开的网页语音 SDK 和许可证，并校验固定版本的 SHA-256；不使用 API Key、不发起通话。若提示版本变化，应先核对 SDK 更新说明和兼容性，再更新校验值。

打开 <http://127.0.0.1:18227/#robots>。这是完整工作台入口。若需要额外的本地预览端口，可在第二个终端运行 `npm run preview:workbench`，打开 <http://127.0.0.1:18228/#robots>；18228 依赖 18227 后端，不能单独运行。

| 环境变量 | 含义 |
| --- | --- |
| `PORT` | 后端端口，默认 `18227` |
| `LATENTX_API_BASE` | Voice PaaS 基址 |
| `LATENTX_API_KEY` | Voice PaaS 长期凭证，只用于后端 |
| `LATENTX_MODEL` | 默认运行模型 ID，应为当前 Key 有权限使用的模型 |
| `DESIGN_AGENT_BASE_URL` | Design Agent 服务基址 |
| `DESIGN_AGENT_TOKEN` | Design Agent 访问凭证 |
| `DESIGN_AGENT_ID` | Design Agent 标识 |
| `DESIGN_AGENT_RELEASE_ID` | 可选固定版本；空值表示新会话选择当前已发布版本 |

配置页位于 `/#settings`，保存后写入 `.local/settings.json`，优先于环境变量。服务端配置字段为 `voiceBase`、`voiceKey`、`model`、`designBase`、`designToken`、`agentId`、`releaseId`。Key 输入框留空表示保留已有值，不是清除。更换地址时需同时提供该地址对应的凭证。先结束正在进行的对话，再保存配置；修改环境变量后需重启后端。

固定凭证失效时，请在配置页更新。只有服务方另外提供了可刷新的授权记录，后端才会使用刷新流程；不能假定任意 Key 都能自动续期。

## 3. 创建和使用机器人

1. 在“数字员工”中点击“创建机器人”，选择文本或语音，填写名称。
2. 在“机器人配置”里填写人设、业务规则、基础模型；语音机器人另有音色和停顿判断选项。
3. 如需业务 Skill，填写标识、名称、用途、Markdown 内容及预加载选项。新增、编辑或移除后，点击“保存草稿”。Skill 表单仅修改草稿，保存成功后才提交服务端。
4. 点击“校验”，根据服务返回结果修正配置，再点击“发布配置”。表单改动必须先保存，发布不会代替保存。
5. 新对话使用最新启用的已发布版本；已有会话不会因发布操作自动切换版本。

基础模型选项属于配置中的 `llm`；发布后服务返回的运行模型 ID 用于 IM 和语音启动，两者不要混用。新建机器人默认使用 Mini，音色和模型是否可用以服务方实际授权为准。

当前工具区域只展示已有工具定义，没有完整工具编辑器。Skill 的实际运行效果需通过已发布模型验证；IM 适配当前关闭工具调用，不能把成功保存 Skill 视为已经验证其执行。

### 文本客服 H5

发布文本机器人后，在右侧试用区输入消息，也可点击“独立打开客服 H5”。使用工作台生成的链接，链接包含本地机器人绑定 ID。

- `mode=live`：连接真实服务，多轮文本及流式回复。
- `mode=demo`：组件演示，支持图片、卡片、人工服务等交互样例；不执行真实业务。
- 真实模式目前未接入图片理解、业务卡片操作或人工座席，这些入口禁用。
- 历史文字保存在当前标签页的 `sessionStorage`。刷新后可查看本地历史，但不能恢复已经结束的云端对话上下文，请新建对话继续。
- 当前单个 IM 连接最多 20 轮或 10 分钟；单条消息最多 4000 字，最多 4 个并发 IM 连接。这些是示例应用限制，可在适配层调整。

组件扩展见 [IM H5 开发指南](IM_H5.md)。

### 网页语音

发布语音机器人后点击“开始通话”，允许浏览器使用麦克风，验证双方都能听到声音，再点击结束。服务端申请临时语音凭证，浏览器使用官方 SDK；长期 Key 不进入浏览器。连续发起通话需间隔至少 10 秒。

真实 IM 和语音使用会产生服务用量。接通状态只表示连接建立，需实际说话并听到回复才能确认语音正常。

当前语音表单的开场白尚未接入草稿保存，不能把编辑框内容当作已经生效；后端按已保存配置或默认欢迎语发起通话。需要自定义时，应在合作伙伴适配中按渠道协议保存并传递开场白。

### 对话管理

语音列表和详情读取服务返回的记录、转写及录音。**当前展示的是连接账户范围内的通话，尚未按机器人隔离**；不要将页面入口中的机器人名称视为每条记录的归属证明。文本工作台尚未接入云端历史列表，H5 的本地历史与云端记录是两种数据。

## 4. 使用 Design

1. 配置一个已发布、具备配置设计能力的 Design Agent；其服务需支持当前适配器使用的会话、运行、事件及工作区文件接口。
2. 在机器人中进入 Design，说明业务需求，例如“生成一个售后咨询客服配置，不确定的问题转人工”。
3. 选择或拖入文件，或粘贴图片；附件上传后，通过工作区路径交给 Agent 读取。图片是否能理解、文档是否能读取，取决于服务能力；不是上传成功就一定理解成功。
4. 在同一对话继续修改，例如“只修改回复风格，保持其他字段不变”。需要操作确认时，阅读内容后选择允许或拒绝。
5. 在工作区预览、下载配置文件。输出文件不会自动应用到机器人；需要时手动填入配置表单，或自行扩展导入、校验、发布流程。

输入单文件最多 10 MB，每轮最多 10 个附件；页面接受图片、PDF、文本、Markdown、JSON、CSV、DOCX 和 XLSX。输出区当前只收集 1 MiB 以内的 JSON、Markdown、TXT。支持停止运行，尚无通用工作区删除/重命名功能。重启后端会保留已有消息，但不会自动恢复正在执行的请求。

服务方可参考公开的 [LatenTX Agent Skill](https://api.latenth.com/skills/latentx/SKILL.md) 准备配置设计能力；本项目中的 `design-agent/instructions.md` 只是行为补充，不能代替完整的 Skill 资料。本应用不会创建或发布远端 Design Agent。

## 5. 二次开发入口

| 要适配的内容 | 修改位置 | 接入要点 |
| --- | --- | --- |
| 品牌、导航、机器人表单 | `examples/workbench/` | 主工作台使用原生 JavaScript；改动后刷新页面 |
| IM 欢迎语和快捷问题 | `src/im-chat/presentation.ts` | 与消息渲染分离，修改后构建 |
| IM 卡片与业务 Action | `cards.tsx`、`card-contracts.ts`、`transport-core.mjs` | 服务端执行真实业务后返回事件；不要以演示动作代替业务成功 |
| 机器人配置、版本及历史 | `server/partner.mjs` | 使用 Voice PaaS 资源 API，保留服务返回的 ID 和版本 |
| IM 通道 | `server/im.mjs`、`src/im-chat/transport.ts` | 保持同一连接的上下文，处理停止、异常和结束 |
| 语音 | `server/index.mjs`、工作台语音交互 | 后端申请临时凭证，前端复用 SDK |
| Design 服务 | `server/design-client.mjs`、`server/design.mjs` | 适配认证、版本、会话、流式事件和文件接口 |
| 配置与数据存储 | `server/settings.mjs` 及各模块的持久化函数 | 将文件存储换成自己的数据库或凭证管理方式 |

公开服务协议： [快速开始](https://api.latenth.com/docs/quickstart.html)、[文本 Realtime](https://api.latenth.com/docs/realtime-api.html)、[网页语音接入](https://api.latenth.com/docs/phone-integration.html)。项目架构及应用接口见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 6. 本地数据与部署适配

`.env` 保存环境配置，`.local/` 保存连接信息、机器人绑定和 Design 会话，均不提交 Git。`.vendor/` 是下载的 SDK，`dist/` 是构建输出，`node_modules/` 是依赖。

机器人列表依据 `.local/partner-robots.json` 中的绑定读取云端配置，不会自动导入账户里的所有机器人。搬迁应用时应妥善迁移自己的绑定和会话数据；仅复制源码会得到空工作区。不要把含凭证的本地数据交给其他客户，也不要在已有绑定的实例中直接切换客户 Key。

当前服务只监听本机，校验本机 Host 和同源 Origin，没有登录、用户权限或客户隔离。部署到合作伙伴域名时，应由应用侧补充 HTTPS、身份与权限、独立凭证/存储，以及可信 Host/Origin 配置；不能只修改监听地址后开放访问。反向代理需支持 IM WebSocket 和 Design SSE，避免缓存或缓冲流式响应。`.local` 文件存储仅适用于单实例起步。

## 7. 常见问题

| 现象 | 检查方法 |
| --- | --- |
| H5 空白或资源 404 | 执行 `npm run build`，确认通过后端地址打开，不直接双击 HTML |
| SDK 404 / 语音无法启动 | 执行 `npm run sync-sdk`，确认 `.vendor` 已生成；检查麦克风权限 |
| 已改 `.env`，页面仍显示旧值 | `.local/settings.json` 优先；通过配置页更新，或备份后清理对应覆盖字段并重启 |
| Key 未开放当前模型 | 默认模型 ID 与可用模型不匹配，向服务方确认权限 |
| 未发布 / 无法试用机器人 | 保存草稿、校验并发布，刷新后开始新对话 |
| Design 401 | 更新 Design 凭证，不要填 Voice PaaS Key |
| Design 无文件或上传失败 | 确认 Agent 已发布，服务支持工作区接口，实际输出文件类型及大小符合限制 |
| Design 等待操作确认 | 在对话中处理确认请求；不要仅等待文本回复 |
| 通话记录包含其他机器人 | 当前为账户范围记录，机器人归属筛选需要扩展 |
| 18228 无法连接后端 | 同时启动 `npm start`；自定义端口时预览进程使用相同 `PORT` |

首次验收建议依次完成：配置检查 → 创建并发布 IM/语音机器人 → IM 两轮上下文 → 实际双向语音 → 通话转写与录音 → Design 生成文件、仅修改一个字段、下载文件。自动测试和构建只能证明本地适配逻辑及资源生成通过，不能替代实际服务验收。
